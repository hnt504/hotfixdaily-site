MCP tools worth knowing: the servers builders actually use

MCP, the Model Context Protocol, is an open standard for connecting AI apps to outside tools and data. Its own docs call it a USB-C port for AI applications. Claude, ChatGPT, VS Code, Cursor and many other apps support it, and the current version of the spec is dated July 28, 2026. An MCP server is the plug-in side: it gives your agent tools like "open a pull request" or "query this table". Below are the servers we think are worth knowing, grouped by job, each described from its own docs.

Code and project tools

GitHub MCP Server Hosted by GitHub, or run locally · MIT

GitHub's official server. Agents can browse and search code, manage issues and pull requests, check GitHub Actions runs and build failures, and review security findings and Dependabot alerts. The hosted version is at api.githubcopilot.com/mcp/.

Our take, best for: Any agent that needs to read or act on your repos.

Source

Linear MCP server Hosted by Linear

Find, create and update Linear issues, projects and comments. Setup uses OAuth, and a read-only endpoint (mcp.linear.app/mcp/readonly) exposes only read tools.

Our take, best for: Letting your coding agent pick up and update tickets.

Source

Sentry MCP Hosted by Sentry, or self-hosted

Built mainly for human-in-the-loop coding agents like Cursor and Claude Code. Its tools focus on developer debugging workflows rather than all of Sentry.

Our take, best for: Fixing production errors with the real stack trace in front of the agent.

Source

Browsers and testing

Playwright MCP Local (Node.js) · Apache-2.0

Browser automation through Playwright using the page's accessibility tree instead of screenshots, so no vision model is needed. Microsoft notes that coding agents may use fewer tokens with its Playwright CLI and skills, and suggests MCP for long-running, stateful browser loops.

Our take, best for: Letting an agent click through your app to test a flow.

Source

Chrome DevTools MCP Local · Apache-2.0

Lets a coding agent control and inspect a live Chrome browser: record performance traces, analyze network requests, read console messages with source-mapped stack traces, and take screenshots. It is also available as a CLI.

Our take, best for: Debugging front-end bugs and slow pages.

Source

Up-to-date docs

Context7 Hosted by Upstash, plus open-source server · MIT

Pulls current, version-specific library docs and code examples into your agent, so it stops guessing at old APIs. Codex's docs use it as their example of adding an MCP server.

Our take, best for: Fast-moving libraries that your model's training data is behind on.

Source

Backend, payments and hosting

Powerful, so read each vendor's security notes before connecting a production account.

Supabase MCP server Hosted at mcp.supabase.com · Apache-2.0

Connects an agent to your Supabase project to manage tables, fetch config and query data. Supabase asks you to read its security best practices first. The local Supabase CLI exposes a smaller set of tools.

Our take, best for: Vibe coders on Supabase who want the agent to set up the schema.

Source

Stripe MCP server Hosted at mcp.stripe.com (public preview)

Lets agents work with the Stripe API and search Stripe's docs and support articles. It connects with OAuth, and Stripe's agent plugins can set it up for you.

Our take, best for: Building and testing payment flows, ideally in test mode first.

Source

Cloudflare MCP servers Hosted by Cloudflare · Apache-2.0

Cloudflare runs several remote MCP servers. It recommends its Cloudflare API server (mcp.cloudflare.com/mcp) for broad API access, with separate servers for docs, sandbox containers and browser rendering. Some older servers are deprecated.

Our take, best for: Builders on Workers and Pages.

Source

Design and docs workspaces

Figma MCP server Hosted (recommended) or desktop app

Gives agents design context to generate code from your Figma files, and can write native Figma content back to the canvas. Writing outside your drafts needs the remote server and a Full seat.

Our take, best for: Turning designs into front-end code that matches your design system.

Source

Notion MCP Hosted by Notion

Notion's hosted server uses OAuth and your existing Notion permissions to search, read and edit pages in Markdown. Notion says its older self-hosted server is no longer actively maintained.

Our take, best for: Agents that read specs or write notes in your Notion workspace.

Source

Finding, testing and building servers

Official MCP Registry Web directory and API

The project's own list of published MCP servers, which it describes as an app store for MCP servers. It launched in preview in September 2025.

Our take, best for: Checking whether an official server exists before you install a random one.

Source

MCP Inspector Web UI, CLI or terminal UI

The official developer tool for inspecting MCP servers. Run npx @modelcontextprotocol/inspector to list a server's tools and try them by hand.

Our take, best for: Seeing exactly what a server exposes before you give it to an agent.

Source

Reference servers Examples from the MCP steering group

A small set of reference servers (Everything, Fetch, Filesystem, Git, Memory, Sequential Thinking, Time). The repo says they are educational examples, not production-ready tools.

Our take, best for: Learning how to build your own server.

Source

How to choose (our take)

  • Start with two. GitHub plus one docs server (Context7) covers most coding-agent sessions. Add others when a task needs them.
  • Prefer the vendor's own server. GitHub, Linear, Sentry, Supabase, Stripe, Cloudflare, Figma and Notion all run official ones. Check the MCP Registry before installing a community server.
  • Read-only first. Use read-only modes or scopes where they exist (Linear has a read-only endpoint), and test against a dev project, not production.
  • Building your own agent? The same servers plug into agent frameworks too. See AI agent frameworks compared.
  • Fewer servers, sharper agent. Every server adds tool descriptions to the model's context. Microsoft's Playwright team points coding agents to a CLI plus skills for that reason.

Where to add an MCP server in your tools

  1. Claude Code. Run claude mcp add, or share servers with your team in a project .mcp.json file. Source
  2. Cursor. Install from the Customize page or the Cursor Marketplace, or configure servers in mcp.json. Source
  3. Codex. Run codex mcp add; settings live in ~/.codex/config.toml. Source
  4. VS Code with Copilot. Add servers through the guided flow or an mcp.json file. Source

Checklist before you ship

  • Only connect servers from sources you trust. Claude Code's docs warn that servers which fetch outside content can expose you to prompt injection.
  • Give each server the smallest access it needs: read-only scopes, a test-mode key, a dev database.
  • Look at the tool list with MCP Inspector before an agent gets it.
  • Keep tokens in environment variables or OAuth, never pasted into prompts or committed config.

FAQ

What is MCP (Model Context Protocol)?

An open-source standard for connecting AI applications to external systems such as files, databases, tools and workflows. An app that supports MCP (the client) can use any MCP server, so a tool is built once and works in many agents.

Which apps support MCP?

Claude, ChatGPT, Claude Code, Cursor, VS Code with Copilot and Codex all document MCP support, along with many other clients and agent frameworks.

What's the difference between a local and a remote MCP server?

A local server runs on your machine, usually started by your agent with a command like npx. A remote server is hosted by the vendor at a URL and usually signs you in with OAuth. Many vendors, including GitHub, Linear, Stripe and Notion, now recommend their hosted servers.

Are MCP servers safe?

They act with whatever access you give them, so treat them like any integration. Use official servers, read-only scopes and test accounts where you can, and review the tool list first. The MCP project publishes security best practices.

Is MCP being replaced by CLIs and skills?

Not replaced, but some teams now suggest both. Microsoft's Playwright docs say coding agents increasingly favor a CLI plus skills because it uses fewer tokens, while MCP still suits long-running, stateful work.
